# 相册故事导演：概要方案说明

项目名称：相册故事导演 / Memory Director  
适用赛题：AI 时代下的智能相册  
文档版本：v0.1  
编写日期：2026-09-30

---

## 1. 方案一句话

**相册故事导演** 是一个基于系统相册原始图片、视频、实况素材的 AI 创作能力。它通过多模态理解识别照片中的人物、地点、事件、情绪和动作，再由 LLM 像导演一样规划故事线、分镜、旁白、字幕、音乐氛围和展示节奏，最终把沉睡在相册里的静态照片和实况片段自动生成有故事性、氛围感、可分享的影像作品。

---

## 2. 背景与问题

### 2.1 用户现状

用户每天拍摄大量照片、视频和实况内容，但绝大多数素材只被存储，很少被二次整理和表达。尤其是亲子成长、家庭陪伴、旅行、毕业、宠物、节日聚会等高情感价值场景，用户往往拍了很多，却很少主动回看、剪辑或分享。

典型问题包括：

1. **素材沉睡**：相册中大量照片只在拍摄当天被浏览，之后长期不再打开。
2. **整理成本高**：用户需要手动翻找、筛选、排序、配文、配乐和剪辑，时间成本过高。
3. **表达门槛高**：普通用户很难把照片组织成有开端、发展、高潮和结尾的故事。
4. **实况素材浪费**：系统相册中的实况照片、Motion Photo、短视频往往包含微动作和声音，但在传统相册回忆中利用不足。
5. **模板同质化**：现有模板视频容易“好看但不懂我”，缺少基于个人相册上下文的叙事。

### 2.2 赛题机会

赛题要求基于系统相册已有图片、视频、实况进行创作，并强调内容吸引力和让封存数据重新“活”起来。这意味着方案不能只做 AI 空生成，也不能只做传统检索或模板剪辑，而应围绕真实相册数据进行理解、重组和表达。

因此，本方案将 AI 的角色定义为 **记忆导演**：

- 它先理解素材，而不是直接套模板；
- 它先组织故事，而不是随机挑图；
- 它先生成可解释分镜，再渲染最终作品；
- 它让用户看到“为什么这些照片值得被串成一个故事”。

## 3. 目标用户与高价值场景

### 3.1 目标用户

| 用户类型 | 典型需求 | 方案价值 |
|---|---|---|
| 家庭用户 | 记录家人、孩子、宠物和节日 | 自动生成温暖回忆，降低整理成本。 |
| 年轻用户 | 旅行、聚会、毕业、情侣纪念 | 生成适合社交分享的故事短片。 |
| 内容轻创作者 | 希望快速生成有质感作品 | 提供低门槛故事脚本和视频初稿。 |
| 长期手机用户 | 相册多年积累但难以回看 | 主动唤醒旧照片，发现被遗忘的故事。 |
| ColorOS 用户 | 希望系统相册更智能 | 在系统相册内完成从发现到创作的闭环。 |

### 3.2 核心场景

#### 场景一：亲子成长故事

用户相册中有大量孩子照片，但分散在不同年份、地点和家庭活动中。相册故事导演可自动识别同一孩子的成长阶段，生成“从第一次走路到第一次旅行”的成长短片。

#### 场景二：家庭陪伴故事

用户和父母、伴侣、朋友在多年中有零散合照。系统可挖掘长期时间线，生成“这些年我们一起走过的地方”的温暖回忆。

#### 场景三：旅行电影

用户一次旅行拍摄了照片、短视频和实况。系统可按时间、地点、路线和情绪自动组织为旅行 Vlog，加入地图、旁白和音乐节奏。

#### 场景四：旧照唤醒

系统定期从一年前、三年前或更早的相册中发现高故事潜力素材，提示用户“发现一段被遗忘的夏天”。

#### 场景五：节日与聚会回顾

针对春节、生日、毕业、婚礼、演唱会等高情绪场景，系统可自动选择合照、笑脸、祝福、烟花、蛋糕、舞台等关键素材生成短片。

## 4. 产品定位

### 4.1 定位

**系统相册内置的 AI 故事创作引擎。**

它不是专业剪辑工具，也不是普通相册检索工具，而是把系统相册中的个人影像资产转化为有故事、有情绪、有氛围的可分享作品。

### 4.2 与竞品的差异

| 对比对象 | 对方强项 | 本方案差异化 |
|---|---|---|
| Google Photos / Apple Photos | AI 搜索、回忆聚合、系统入口 | 强调 LLM 分镜、故事性评分、实况素材深度利用和可验收中间数据。 |
| 剪映 / CapCut | 模板、特效、音乐、社交传播 | 不与其比专业剪辑，而是基于系统相册长期上下文自动讲个人故事。 |
| Canva | 多格式设计与模板 | 更强调相册原生数据、人物关系、时间线和旧照唤醒。 |
| 照片书产品 | 时间线整理、纪念册商业闭环 | 输出不局限静态成册，可生成动态短片和交互式故事页。 |
| 开源相册项目 | 管理、备份、检索、人脸识别 | 在管理和检索之上增加故事规划、创作表达和评分验收。 |

## 5. 核心方案

### 5.1 总体流程

```text
系统相册素材
  -> 媒体采集与解析
  -> 图片/视频/实况统一建模
  -> 多模态理解生成素材卡
  -> 时间/地点/人物/语义聚类生成事件簇
  -> LLM 规划故事线与分镜
  -> 故事性评分与风险检查
  -> 渲染故事页或短视频
  -> 用户编辑、分享、保存
```

### 5.2 核心能力

| 能力 | 说明 | 初赛实现方式 | 决赛增强方向 |
|---|---|---|---|
| 素材统一建模 | 将图片、视频、实况统一为 Asset Card | 基于样例数据生成 JSON | 接入 Android MediaStore 与实况解析。 |
| 多模态理解 | 识别人、场景、动作、情绪、质量 | 使用 VLM/规则/模拟标注混合 | 增加端侧视觉模型、OCR、ASR、主体检测。 |
| 事件聚类 | 找出同一场景、同一时间、同一人物的事件 | 时间地点加 embedding 聚类 | 增加关系图谱和长期记忆图谱。 |
| 故事规划 | 生成主题、标题、故事弧、分镜、旁白 | LLM 输出 Story Plan JSON | 支持多风格、多版本、用户偏好学习。 |
| 故事评分 | 量化故事性和可分享性 | StoryScore 多维评分 | 增加用户反馈闭环和 A/B 评估。 |
| 实况利用 | 从 Live/Motion Photo 中抽取微动作 | 初赛用样例 best segment | 决赛接入真实视频段抽取、音频和关键帧。 |
| 渲染输出 | 生成故事页或短片 | Web 故事页 + 基础视频 | 增加卡点、转场、字幕、配乐、电影滤镜。 |

## 6. MVP 范围

### 6.1 初赛 MVP 目标

初赛目标是证明“相册故事导演”的核心闭环可行，重点不在极致视觉效果，而在可解释的数据组织和故事性评估。

初赛 Demo 应完成：

1. 输入一组样例相册素材数据，覆盖图片、视频、实况三类。
2. 生成结构化 `asset_cards.json`，描述每个素材的时间、地点、人物、场景、情绪、质量和动作。
3. 生成 `event_clusters.json`，把素材聚合成若干可讲述事件。
4. 用户输入或选择主题，例如“温暖的家庭夏天”。
5. LLM 生成 `story_plan.json`，包含标题、风格、分镜、旁白、字幕和素材引用。
6. 生成 `story_score.json`，输出故事性评分和评分理由。
7. Web 或 App Demo 展示故事页，并可播放基础短片或分镜预览。

### 6.2 初赛暂不做的内容

为保证可行性，初赛阶段建议暂不追求以下能力：

- 不做完整系统相册权限接入，可哑模拟所有手机厂商相册格式。
- 不做复杂图生视频，避免算力和人物失真风险。
- 不做多用户云相册同步。
- 不做完整商业化模板市场。
- 不做全量端侧模型训练，只使用现成模型或模拟结构化识别结果。

### 6.3 决赛增强范围

决赛重点增强作品效果：

- 接入真实实况/Motion Photo 视频段；
- 提取 best segment，优先选择有动作、有笑声、有环境音的片段；
- 按音乐 BPM 做镜头节奏；
- 加入旁白、字幕、转场、滤镜、Ken Burns 运镜；
- 支持多种风格模板，例如“温暖纪录片”“电影预告”“旅行 Vlog”“亲子成长”；
- 增加端侧资源占用评估与隐私风险拦截。

## 7. Demo 设计

### 7.1 Demo 页面结构

| 页面 | 作用 | 展示内容 |
|---|---|---|
| 首页 | 展示 AI 发现的故事 | 推荐卡片、主题、时间跨度、主角、封面。 |
| 素材理解页 | 展示可验收数据 | Asset Card、caption、人物、地点、质量、motion score。 |
| 事件聚类页 | 展示故事来源 | 事件簇、时间线、地点、主题标签、入选素材。 |
| 故事导演页 | 展示 LLM 创作过程 | 标题、故事弧、分镜、旁白、音乐风格、镜头说明。 |
| 评分解释页 | 展示故事性评估 | StoryScore 雷达图、分项分数、风险提示。 |
| 作品预览页 | 展示最终效果 | 交互式故事页或 30-60 秒短片。 |

### 7.2 用户操作路径

```text
打开 Demo
  -> 选择样例相册
  -> 点击“AI 发现故事”
  -> 查看系统推荐的故事主题
  -> 选择风格
  -> 生成分镜
  -> 查看故事性评分
  -> 预览作品
  -> 编辑标题/删除敏感素材
  -> 分享或保存
```

### 7.3 推荐演示脚本

演示时建议使用一个完整故事，例如“一个夏天的家庭旅行”。素材包含：出发、路上、到达景点、孩子奔跑的实况、晚餐合照、日落短视频、返程照片。这样可以清晰展示时间推进、人物连续、情绪变化和动态素材利用。

## 9. 验收维度与方式

### 9.1 初赛验收维度

| 维度 | 验收问题 | 产物 |
|---|---|---|
| 数据完整性 | 是否覆盖图片、视频、实况素材 | `asset_cards.json`。 |
| 数据可读性 | 评委是否能看懂每个素材为什么被选中 | 素材 caption、标签、质量分、motion 信息。 |
| 事件组织能力 | 是否能把素材聚成合理事件 | `event_clusters.json`。 |
| 故事规划能力 | 是否生成清晰故事线和分镜 | `story_plan.json`。 |
| 故事性评估 | 是否能量化故事好坏并解释 | `story_score.json`。 |
| 展示完整性 | 是否能看到最终作品 | Demo 页面或视频预览。 |
| 风险兜底 | 是否避免敏感内容和 LLM 幻觉 | 风险检测结果、降级策略说明。 |

### 9.2 建议量化指标

| 指标 | 目标值 | 计算方式 |
|---|---:|---|
| 素材入选准确率 | >= 80% | 人工标注“是否符合主题”，统计入选素材正确比例。 |
| 事件聚类合理率 | >= 80% | 人工判断每个事件簇是否为同一事件。 |
| 故事线满意度 | >= 4/5 | 评委或测试用户对故事连贯性打分。 |
| 素材多样性 | >= 0.7 | 场景、时间、景别、媒体类型的归一化多样性分。 |
| 动态素材利用率 | >= 30% | 作品中视频/实况素材时长占比。 |
| 老照片唤醒率 | >= 40% | 作品中距当前超过 30 天素材的占比。 |
| 平均生成耗时 | <= 60 秒 | 从点击生成到可预览作品完成的时间。 |
| 敏感内容漏出率 | 0 | 人工检查是否包含证件、车牌、隐私地址等敏感内容。 |

### 9.3 验收数据集建议

初赛可准备 3 组样例相册：

| 样例集 | 素材规模 | 内容 | 用途 |
|---|---:|---|---|
| 家庭夏日 | 30-50 个素材 | 亲子、公园、日落、实况奔跑 | 验证温暖故事和实况利用。 |
| 城市旅行 | 40-80 个素材 | 火车、酒店、景点、美食、地图位置 | 验证时间地点聚类和旅行叙事。 |
| 毕业聚会 | 30-60 个素材 | 合照、舞台、朋友、聚餐、短视频 | 验证多人场景和高潮片段选择。 |

## 11. 可行性分析

### 11.1 为什么初赛可落地

1. **可以从样例数据开始**：赛题要求用于创作的数据可读，初赛可用样例相册和 JSON 数据证明算法闭环。
2. **无需重模型训练**：素材理解可使用现成 VLM/CLIP/规则和少量人工标注混合实现。
3. **LLM 输出结构化 JSON**：分镜和旁白可通过 prompt 约束生成，便于验收。
4. **渲染可先做轻量版**：初赛用 Web 故事页或基础 FFmpeg 视频即可，不依赖复杂图生视频。
5. **每一步都有中间产物**：素材卡、事件簇、分镜和评分均可被评委直接查看。

### 11.2 技术风险可控

| 风险 | 控制方式 |
|---|---|
| VLM 识别不准 | 多信号融合，关键样例可人工校正，低置信度不进入旁白。 |
| LLM 编故事过度 | 旁白必须引用素材证据，不确定时使用保守描述。 |
| 生成视频成本高 | 初赛先故事页和基础剪辑，决赛再增强电影感。 |
| 隐私风险 | 敏感检测、分享前确认、默认端侧处理。 |
| 素材不足 | 降级为“精选相册卡片”或提示用户补充素材。 |

## 12. 总结

相册故事导演将系统相册从“存储照片的地方”升级为“理解记忆并主动创作的 AI 导演”。它符合赛题对原始相册数据、故事性、吸引力和旧照唤醒的要求，也能与 ColorOS 系统相册的入口、权限、隐私和端侧能力形成天然结合。

初赛建议聚焦 **数据组织 + 故事规划 + 故事性评分 + 可预览作品**；决赛再重点强化 **实况素材利用 + 音画搭配 + 电影感渲染**。
