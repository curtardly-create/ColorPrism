# 相册故事导演：详细设计说明

项目名称：相册故事导演 / Memory Director  
适用赛题：AI 时代下的智能相册  
文档版本：v0.1  
编写日期：2026-09-30

---

## 1. 设计目标

### 1.1 产品目标

基于系统相册中已有的图片、视频、实况内容，自动挖掘可讲述的生活故事，并生成有故事性、氛围感和分享价值的影像作品。

### 1.2 技术目标

构建一条可落地、可验证、可扩展的 AI 相册创作流水线：

```text
媒体资产接入
  -> 元数据解析
  -> 多模态理解
  -> 素材卡构建
  -> 事件聚类
  -> 故事候选生成
  -> LLM 分镜规划
  -> 故事性评分
  -> 风险检查
  -> 作品渲染
```

### 1.3 初赛交付目标

初赛重点体现故事性代码实现框架，尤其是数据组织和故事性评估。因此本设计优先保证：

- 数据结构清晰可读；
- 每个创作决策可追溯；
- LLM 输出结构化可验收；
- 故事性评分可解释；
- Demo 能展示从素材到作品的完整闭环。

## 3. 关键流程设计

### 3.1 流程一：素材接入与统一建模

输入：系统相册中的图片、视频、实况素材。  
输出：统一的 `AssetCard`。

处理步骤：

1. 扫描素材基础信息：文件 ID、媒体类型、拍摄时间、文件路径、尺寸、时长。
2. 读取 EXIF：GPS、设备型号、焦距、曝光、方向、拍摄时间。
3. 视频/实况处理：抽取封面帧、关键帧、短音频信息、可用动作片段。
4. 生成缩略图和低分辨率分析图，避免直接处理原图导致内存过高。
5. 写入 `AssetCard`，作为后续所有 AI 模块的统一输入。

关键原则：

- 不区分图片、视频、实况的上层使用方式，统一抽象为“可参与故事编排的镜头素材”。
- 原始文件只在渲染阶段读取，分析阶段尽量使用缩略图、关键帧和摘要。
- 所有 AI 判断必须保留置信度和证据，便于解释与兜底。

### 3.2 流程二：多模态理解

输入：`AssetCard` 的基础字段和缩略图/关键帧。  
输出：丰富后的素材语义信息。

识别内容包括：

| 类型 | 字段 | 示例 |
|---|---|---|
| 人物 | `people` | `p01: child, happy, face_clear=0.91` |
| 场景 | `scene_tags` | `beach, sunset, family, travel` |
| 物体 | `objects` | `cake, balloon, suitcase, dog` |
| 动作 | `actions` | `running, hugging, waving, dancing` |
| 情绪 | `emotion` | `warm, joyful, quiet, exciting` |
| 文本 | `ocr_text` | 横幅、路牌、票据、毕业证书文字。 |
| 音频 | `audio_tags` | 笑声、掌声、海浪、音乐、讲话。 |
| 质量 | `quality` | 清晰度、曝光、人脸质量、美学评分。 |
| 语义 | `semantic_caption` | “傍晚孩子在海边奔跑，父母在后面微笑”。 |

初赛可采用三种实现混合：

1. 对少量样例素材人工预标注，保证演示稳定。
2. 使用 VLM 生成 caption 和标签。
3. 使用规则计算质量、时间、地点和媒体类型特征。

### 3.3 流程三：事件聚类

输入：一组 `AssetCard`。  
输出：多个 `EventCluster`。

聚类依据：

| 依据 | 权重建议 | 说明 |
|---|---:|---|
| 时间接近度 | 0.30 | 同一天、同一小时、连续拍摄更可能属于同一事件。 |
| 地点接近度 | 0.20 | GPS 距离、城市、POI、室内外场景。 |
| 人物重合度 | 0.20 | 主角一致或合照人物高度重合。 |
| 语义相似度 | 0.20 | caption、场景标签和 embedding 相似。 |
| 媒体互补性 | 0.10 | 图片、视频、实况组合更适合成片。 |

初赛聚类策略：

```text
1. 按拍摄日期切分粗粒度候选集。
2. 在同一天内按时间间隔和地点距离切分事件。
3. 对边界模糊的事件使用语义相似度合并。
4. 计算每个事件的故事潜力分。
5. 选择 Top-K 事件进入故事规划。
```

### 3.4 流程四：故事候选生成

系统从事件簇中发现可讲述的故事候选。

故事候选类型：

| 类型 | 识别条件 | 示例 |
|---|---|---|
| 单事件故事 | 一个事件内部素材丰富、情绪强 | “生日那天的惊喜”。 |
| 多事件时间线 | 同一人物跨多个时间段 | “宝宝从春天到夏天的成长”。 |
| 地点旅行故事 | 多个地点连续出现 | “三天两夜的厦门旅行”。 |
| 关系故事 | 两个或多人长期共同出现 | “我和妈妈这些年”。 |
| 主题故事 | 同一主题跨时间出现 | “那些有海风的日子”。 |

候选筛选规则：

- 素材数量不少于 8；
- 至少包含 1 个高质量人物或场景素材；
- 至少包含 1 个动态素材，若没有则必须有高情绪照片；
- 主角或主题一致性高于阈值；
- 隐私风险低于阈值。

### 3.5 流程五：LLM 分镜规划

输入：故事候选、用户主题、素材摘要。  
输出：结构化 `StoryPlan`。

LLM 的职责不是直接生成最终视频，而是作为“导演”输出创作决策：

- 故事标题；
- 故事主题；
- 叙事结构；
- 镜头顺序；
- 每个镜头使用哪个素材；
- 对实况/视频使用哪一段；
- 字幕和旁白；
- 音乐情绪；
- 转场和运镜建议；
- 风险提示。

Prompt 约束要点：

```text
你是相册故事导演。只能基于输入素材摘要进行创作，禁止编造不存在的人物、地点和事件。
请输出 JSON，不要输出 Markdown。
每个 scene 必须引用 asset_id。
旁白如果缺少证据，只能使用“那一天”“这段时光”等保守表达。
不要输出可能暴露精确住址、证件号码、车牌号的信息。
```

### 3.6 流程六：故事性评分

输入：`StoryPlan`、`EventCluster`、`AssetCard`。  
输出：`StoryScore`。

评分维度：

| 维度 | 权重 | 说明 |
|---|---:|---|
| 主题一致性 | 0.20 | 素材是否围绕同一主题。 |
| 时间连续性 | 0.15 | 是否有自然的时间推进。 |
| 人物连续性 | 0.15 | 主角是否稳定、关系是否清晰。 |
| 情绪曲线 | 0.20 | 是否有开端、发展、高潮和收束。 |
| 视觉丰富度 | 0.10 | 是否有不同场景、景别和构图。 |
| 动态素材价值 | 0.10 | 实况/视频是否提供关键动作和声音。 |
| 用户意图匹配 | 0.10 | 是否符合用户输入主题和风格。 |
| 隐私风险 | 扣分项 | 敏感内容越高，扣分越多或直接拦截。 |

公式：

```text
StoryScore =
  0.20 * theme_consistency +
  0.15 * time_continuity +
  0.15 * character_continuity +
  0.20 * emotion_curve +
  0.10 * visual_diversity +
  0.10 * motion_richness +
  0.10 * user_intent_match -
  0.20 * privacy_risk
```

### 3.7 流程七：渲染输出

初赛输出两种形式：

1. **交互式故事页**：按分镜展示素材、标题、旁白、字幕、评分和解释。
2. **基础短视频**：使用图片、视频和实况片段生成 30-60 秒视频。

渲染策略：

- 图片素材使用轻量运镜，例如 slow zoom、pan、fade；
- 实况素材使用 `best_segment`；
- 视频素材裁剪关键片段；
- 字幕来自 `StoryPlan.scenes.caption`；
- 旁白可先用文本展示，决赛再接 TTS；
- 音乐初赛可用固定免版权背景乐，决赛按情绪/BPM 匹配。

## 5. 核心算法设计

### 5.1 素材质量评分

目标：避免糊图、闭眼、重复图和无主体图片进入故事。

建议评分：

```text
AssetQuality =
  0.25 * sharpness +
  0.20 * exposure +
  0.20 * face_quality +
  0.20 * aesthetic +
  0.15 * uniqueness
```

规则：

- `sharpness < 0.3` 的图片默认不入选；
- `duplicate_score > 0.85` 的重复素材只保留质量最高的一张；
- 人物故事优先选择人脸清晰、表情积极的素材；
- 旅行故事优先选择地点代表性强、景别多样的素材。

### 5.2 实况素材 best segment 抽取

目标：从实况或短视频中找到最适合参与故事的 1-3 秒片段。

候选信号：

| 信号 | 说明 |
|---|---|
| 主体运动 | 人物跑动、挥手、拥抱、转身等动作。 |
| 表情变化 | 从平静到笑、惊喜、欢呼。 |
| 音频峰值 | 笑声、掌声、海浪、风声、现场声。 |
| 镜头稳定性 | 避免剧烈抖动和快速模糊。 |
| 关键帧质量 | 保证片段中至少有清晰主体。 |

初赛可用简化规则：

```text
MotionScore =
  0.35 * optical_flow_strength +
  0.25 * subject_consistency +
  0.20 * audio_energy +
  0.20 * keyframe_quality
```

### 5.3 事件故事潜力评分

目标：从多个事件簇中选择最值得创作的候选。

```text
EventStoryPotential =
  0.25 * coherence +
  0.20 * emotion_strength +
  0.15 * main_character_strength +
  0.15 * visual_diversity +
  0.15 * motion_richness +
  0.10 * old_memory_value
```

其中 `old_memory_value` 用于体现“封存数据重新活起来”：

```text
old_memory_value = min(days_since_capture / 365, 1.0)
```

### 5.4 分镜排序策略

LLM 生成分镜前，系统先提供候选排序建议，避免完全依赖大模型。

排序原则：

1. 开头使用环境交代或情绪强的素材；
2. 中段使用动作、互动和细节素材；
3. 高潮使用笑脸、拥抱、奔跑、合照、舞台等强情绪素材；
4. 结尾使用日落、背影、合照、安静场景等收束素材；
5. 避免连续使用高度相似照片；
6. 视频/实况片段穿插使用，提升节奏变化。

### 5.5 隐私与安全检测

拦截和提示对象：

- 身份证、护照、银行卡、票据号码；
- 车牌、门牌、家庭住址、学校名称等敏感地点；
- 儿童近距离可识别照片；
- 医疗、病历、裸露、暴力等敏感场景；
- 未经确认的人脸密集场景。

策略：

| 风险等级 | 处理方式 |
|---|---|
| 低风险 | 正常生成，分享前提示。 |
| 中风险 | 默认打码或不展示敏感字段。 |
| 高风险 | 默认不入选，需要用户手动确认。 |

## 6. LLM 编排设计

### 6.1 输入给 LLM 的内容

LLM 不直接读取原图，而读取结构化摘要，降低隐私和成本。

```json
{
  "user_intent": "生成一个温暖、电影感的家庭夏日回忆",
  "duration_sec": 45,
  "target_ratio": "9:16",
  "candidate_events": [
    {
      "event_id": "evt_2024_summer_family_park",
      "event_caption": "一家人在夏天傍晚去公园放风筝...",
      "asset_summaries": [
        {
          "asset_id": "IMG_20240601_001",
          "asset_type": "live_photo",
          "caption": "孩子向镜头跑来，风筝在背景中晃动",
          "people": ["p01", "p02"],
          "emotion": "happy",
          "quality": 0.82,
          "motion_score": 0.79
        }
      ]
    }
  ]
}
```

### 6.2 输出约束

LLM 必须输出符合 Schema 的 JSON：

- `story_id` 必填；
- `title` 必填；
- `duration_sec` 必填；
- `style` 必填；
- `scenes` 必填且不少于 6 个；
- 每个 scene 必须引用存在的 `asset_id`；
- 每句旁白必须可由素材摘要支持；
- 不允许输出精确地址和证件信息；
- 不允许编造未出现的人名和亲属关系。

### 6.3 幻觉控制

| 问题 | 控制方式 |
|---|---|
| 编造人物关系 | 输入只给 `person_id` 和低置信 role，旁白使用“他们”“家人”“朋友”等保守表述。 |
| 编造地点 | 只允许使用 `location_summary` 中的城市或 POI，精确位置默认隐藏。 |
| 编造情节 | scene 必须绑定 `evidence` 字段，说明来自 caption、timestamp、motion 或 OCR。 |
| 输出格式错误 | 使用 JSON Schema 校验，失败后自动要求模型修复。 |
| 风格过度煽情 | Prompt 限制文案长度、语气和事实边界。 |

| 环节 | 端侧 | 云侧 |

|---|---|

## 9. 评价体系

### 9.1 技术指标

| 指标 | 目标 | 说明 |
|---|---:|---|
| 素材分析完成率 | >= 95% | 样例素材都能生成 AssetCard。 |
| 事件聚类合理率 | >= 80% | 人工标注同一事件对比。 |

| Demo 生成耗时 | <= 60 秒 | 使用样例相册从点击到预览。 |

### 9.2 用户体验指标

| 指标 | 目标 | 说明 |
|---|---:|---|
| 故事连贯性 | >= 4/5 | 评委或测试用户主观评分。 |
| 情绪感染力 | >= 4/5 | 是否有温度、氛围和记忆感。 |

对比指标：故事连贯性、情绪感染力、素材重复率、用户编辑次数、分享意愿。

## 10. 风险与兜底方案

### 10.1 素材不足

表现：某个主题下照片数量少、质量差或没有动态素材。  
兜底：

- 降级为故事卡片或精选相册；
- 扩大时间范围；
- 提示用户补充素材；
- 改用更宽泛主题，例如从“毕业典礼”变为“那段校园时光”。

### 10.2 识别错误

表现：人物识别错、地点识别错、场景 caption 不准确。  
兜底：

- 低置信结果不进入旁白；
- 不直接称呼具体关系；
- 提供用户删除和替换；
- 在数据中保留 confidence，评分时降低权重。

### 10.3 LLM 幻觉

表现：生成不存在的故事情节、人物关系或地点。  
兜底：

- Prompt 明确禁止编造；
- scene 必须引用 `asset_id` 和 `evidence`；
- 使用 JSON Schema 校验；
- 对旁白做事实检查，不符合素材证据则重写。

### 10.4 隐私泄露

表现：作品中出现证件、车牌、家庭住址、儿童敏感图像。  
兜底：

- 默认端侧检测；
- 高风险素材不入选；
- 中风险素材打码或模糊；
- 分享前显示“可能包含敏感信息”的确认页。

### 10.5 审美不佳

表现：作品节奏平淡、重复图多、转场突兀。  
兜底：

- 质量评分过滤；
- 重复素材去重；
- 限制同一场景连续出现次数；
- 提供多个风格版本让用户选择。

### 10.6 算力和耗电

表现：分析全量相册耗时、发热、耗电。  
兜底：

- 分层分析，先缩略图后原图；
- 闲时、充电、WLAN 下增量索引；
- 优先分析最近和高价值事件；
- 缓存素材卡和 embedding。

## 16. 总结

本设计以系统相册中的真实图片、视频和实况为基础，通过统一素材卡、事件聚类、LLM 分镜、故事性评分和轻量渲染，构建一个可落地的 AI 相册创作框架。

初赛阶段应把重点放在 **可解释数据组织和故事性评估**，用结构化 JSON 和可视化 Demo 证明方案可行；决赛阶段再强化 **实况素材利用、音画同步和电影感表现**，形成更强的用户感知和技术亮点。
